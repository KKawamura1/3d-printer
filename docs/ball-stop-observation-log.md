# ボール走行の停止観察ログ（連結相性・原因切り分け）

## 目的

デュプロ互換の3Dプリント製ボールコースで、**どのパーツをどの順で接続すると、どこで、どの程度の頻度で止まるか**を蓄積する。単体不良・接続相性・設置条件を分け、特定パーツを早計に犯人扱いしない。

- **追記する一次データ:** [`measurements/ball-rolling-stop-observations.csv`](../measurements/ball-rolling-stop-observations.csv)。1行＝1つの**有向**接続（上流→下流）×条件×観察セット。別の日、固定方法、ボール、パーツ版、反転方向を変えたら**別行**にする。過去の失敗記録は消さない。
- **対策・原因仮説・作業:** [Issue #77](https://github.com/KKawamura1/3d-printer/issues/77)。CSVには確定していない原因を断定して書かない。
- `BS-YYYYMMDD-NNN` を観察IDとして採番する。回数が不明なら `attempts` / `stops` は**空欄**とし、`frequency_qualitative` に「frequent」等の定性的表現を残す。日時は報告日と観察日を混同しない（観察日未確認なら報告日だけ記録）。

## 次回からの記録ルール

追加報告は「`S02-V16 → E01-V8`、`E01-V8` 入口で停止」のような短文だけでも、その時点で分かる事実を追記する。詳細が分かるときだけ以下を併記する。

1. 上流・下流の**刻印ID＋版**、連結方向（必須。単体内の停止なら下流は空欄）。
2. **止まった場所**（上流末端／境界／下流入口／下流内部／不明）。境界の前後どちらかも分かれば記録。
3. **同条件の試行回数と停止回数**（例：10回中7回）。「よく」は定量化せず原文を残す。
4. **条件**（使用球、投入高さや速度、接続を手で固定したか、土台・傾き、印刷品の個体、バリ除去有無など）。不明は空欄のまま。
5. 改善・悪化した操作（押さえる、傾ける、パーツを交換、順番を逆にする等）。観察と推測を分ける。

### 「誰が悪いか」の比較手順

1. **同じ下流（例：`E01-V8`）**に別の上流パーツをつなぐ。どれでも入口で止まれば下流入口・据付条件の疑いが強まる。
2. **同じ上流（例：`S02-V16`）**から別の下流へつなぐ。どれでも境界で止まれば上流出口・速度条件の疑いが強まる。
3. **同じペアを固定あり／なし**で比較。固定で改善すれば段差・傾き・がたつきの寄与を疑う。
4. **各パーツ単体でも走らせる**。単体が良くても連結で止まるなら接続相性の可能性を残す。
5. できれば各条件10回、同じ球と投入条件で比較して `stops/attempts` を保存。試験していない数値は補完しない。

停止率の集計は観察数が十分にたまってから、上流ID・下流ID・ペア・設置条件それぞれで行う。**条件差を無視して停止数だけで原因を断定しない。**
